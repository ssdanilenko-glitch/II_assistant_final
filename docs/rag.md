

# RAG-пайплайн: retrieve → rerank → synthesize

## Общее описание

RAG (Retrieval-Augmented Generation) — это подход, при котором ответ на вопрос генерируется на основе релевантных фрагментов из базы знаний, найденных перед вызовом LLM. Это позволяет значительно снизить галлюцинации и давать ответы, подкреплённые источниками.

В проекте RAG-пайплайн построен по принципу **«retrieve → guard → synthesize»**:

1. **Retrieve** – поиск релевантных чанков в векторной базе Qdrant.
2. **Rerank** (опционально) – пересортировка найденных фрагментов с использованием модели реранкинга для повышения точности.
3. **Synthesize** – генерация ответа LLM на основе отобранных фрагментов с указанием источников.

Пайплайн реализован в классе `RAGService` (`app/services/rag.py`). Он инициализируется один раз при старте приложения и используется для всех запросов.

## Архитектура пайплайна


graph LR
    A[Вопрос пользователя] --> B[Retrieve]
    B --> C[Qdrant (dense-поиск)]
    C --> D[10 кандидатов]
    D --> E{Реренкер включён?}
    E -->|Да| F[SentenceTransformerRerank]
    F --> G[5 лучших]
    E -->|Нет| H[Обрезка до 5]
    G --> I[Проверка порога релевантности]
    H --> I
    I -->|score >= 0.62| J[Синтез ответа]
    I -->|score < 0.62| K[Отказ (confident=False)]
    J --> L[Ответ с цитатами]


---

## Этап 1. Retrieve (поиск)

На этом этапе запрос пользователя преобразуется в вектор с помощью эмбеддинг-модели `BAAI/bge-m3` и выполняется поиск по коллекции `rag_block_04` в Qdrant.

**Параметры поиска:**

| Параметр | Значение | Описание |
|----------|----------|----------|
| `rag_retrieve_top_k` | 10       | Количество кандидатов, возвращаемых из Qdrant |
| `rag_rerank_top_n` | 5        | Количество фрагментов после реранкинга (или обрезки) |
| `rag_score_threshold` | 0.62     | Минимальный порог релевантности (top-1 score) |
| `rag_use_hybrid` | false    | Включение гибридного поиска (dense + sparse) |
| `rag_restrict_to_internal` | false    | Фильтр по полю `visibility="internal"` |

**Используемый код:**
- `_retrieve()` – асинхронный вызов ретривера.
- `_retrieve_checked()` – обёртка с проверкой инициализации.
- `_vector_store()` – создание подключения к Qdrant.

---

## Этап 2. Rerank (опционально)

Если флаг `rag_use_reranker` установлен в `true`, найденные 10 кандидатов передаются в модель реранкинга `BAAI/bge-reranker-v2-m3`. Эта модель пересортировывает фрагменты по релевантности запросу, оставляя только `rag_rerank_top_n` (5) лучших.

**Почему реранкер полезен:**
- Улучшает точность на сложных запросах.
- Позволяет обойти ограничения dense-поиска (например, когда семантически похожие фрагменты не совпадают по смыслу).

Если реранкер выключен, выполняется простая обрезка dense-топа до `rag_rerank_top_n` (5).

**Используемый код:**
- `_build_reranker()` – создание экземпляра `SentenceTransformerRerank`.
- `_postprocessors` – список постпроцессоров, применяемых к результатам поиска.

---

## Этап 3. Synthesize (синтез ответа)

На этом этапе отобранные фрагменты (5 штук) используются для генерации ответа через локальную LLM (Ollama с моделью `frob/qwen3.5-instruct:4b`). Запрос строится по шаблону `CITATION_QA_PROMPT`, который требует, чтобы ответ опирался ТОЛЬКО на предоставленные источники и содержал ссылки на них в виде [1], [2], ...

**Проверка порога:**  
Если **лучший score** (максимальный среди всех найденных) меньше `rag_score_threshold` (0.62), то синтез не выполняется – возвращается честный отказ с `confident=False`. Это предотвращает галлюцинации на нерелевантных документах.

**Формат ответа:**
- `answer` – текст ответа с цитатами (например, `[1 — Инструкция по Wi-Fi.docx]`).
- `sources` – список источников с полями: `id`, `file_name`, `page`, `score`, `snippet`.
- `top_score` – максимальная релевантность среди использованных чанков.
- `confident` – `True`, если ответ был сгенерирован; `False` при отказе.

**Используемый код:**
- `_synthesize()` – основной метод синтеза.
- `CITATION_QA_PROMPT` – шаблон промпта.
- `build_sources()` – формирование структурированных источников.
- `parse_citations()` – преобразование `[1]` в `[1 — file.pdf]`.

## Пример запроса и ответа

**Запрос:**  
> «Как подключиться к сети Wi-Fi BMZ-Internet?»

**Этапы:**
1. Векторный поиск находит 10 чанков.
2. Реранкер (если включён) сортирует их по релевантности.
3. Лучший score = 0.78 > порога 0.62 → синтез выполняется.
4. LLM генерирует ответ:
   > «Для подключения к сети Wi-Fi BMZ-Internet необходимо выбрать сеть “BMZ-Internet” в списке доступных Wi-Fi, ввести пароль «bmz00000» и нажать «Подключиться» [1 — Инструкция по Wi-Fi BMZ-Internet.docx].»

## Настройки в `.env`

| Переменная | Значение по умолчанию     | Описание |
|------------|---------------------------|----------|
| `RAG_RETRIEVE_TOP_K` | 10                        | Количество кандидатов из Qdrant |
| `RAG_RERANK_TOP_N` | 5                         | Количество фрагментов после реранкинга |
| `RAG_SCORE_THRESHOLD` | 0.62                      | Минимальный порог для синтеза |
| `RAG_USE_RERANKER` | false                     | Включить реранкер |
| `RAG_RERANKER_MODEL` | `BAAI/bge-reranker-v2-m3` | Модель для реранкинга |
| `RAG_USE_HYBRID` | false                     | Гибридный поиск (dense + sparse) |
| `RAG_CHUNK_SIZE` | 512                       | Размер чанка при индексации |
| `RAG_CHUNK_OVERLAP` | 64                        | Перекрытие между чанками |

## Заключение

Реализованный RAG-пайплайн обеспечивает:
- **Высокую точность** за счёт реранкинга и порога релевантности.
- **Прозрачность** – ответы сопровождаются ссылками на источники.
- **Гибкость** – все параметры настраиваются через `.env`.
- **Приватность** – все компоненты работают локально, без внешних API.
