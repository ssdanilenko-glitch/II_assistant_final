# Сравнение моделей эмбеддингов

Документ фиксирует выбор модели эмбеддингов для RAG-пайплайна
ИТ-ассистента. Сравнение проведено **на реальном корпусе проекта**
(коллекция `rag_block_04`, 646 чанков из 70 документов) с использованием
golden dataset из 15 вопросов.

## Условия эксперимента

| Параметр | Значение                                             |
|---|------------------------------------------------------|
| Корпус | `rag_block_04`, 646 чанков, 70 уникальных источников |
| Запросы | `tests/eval/golden_dataset.json`, 15 вопросов        |
| Ground truth | все чанки документа, указанного в поле `source`      |
| Метрики | Recall@K, MRR@K, nDCG@K, Hit@K                       |
| K | 1, 3, 5, 10                                          |
| Скрипт | `scripts/compare_embeddings.py`                      |
| Артефакт | `docs/embedding_comparison.json`                     |
| Покрытие ground truth | 15 / 15                                              |

**Запуск:**

```bash
docker compose exec -e HF_HUB_OFFLINE=1 app \
    python scripts/compare_embeddings.py
```

Методика: для каждого вопроса берётся документ-источник из golden
dataset, и все его чанки считаются релевантными. Это даёт
**document-level retrieval**-оценку: находит ли модель нужный документ.

---

## Кандидаты

| Модель | Размерность | Размер (FP16) | Лицензия | On-premise |
|---|---|---|---|---|
| **BAAI/bge-m3** | 1024 (Matryoshka) | ~2.2 GB | MIT | ✅ |
| `intfloat/multilingual-e5-small` | 384 | ~0.5 GB | MIT | ✅ |
| `intfloat/multilingual-e5-large` | 1024 | ~2.2 GB | MIT | ✅ |

Все три — локальные, без внешних API. Модели с внешними провайдерами
(OpenAI, Cohere) в сравнение **не включались** — они противоречат
принципу on-premise (см. [final_decisions.md](final_decisions.md)).

## Результаты

### Hit@K — доля вопросов, где правильный документ попал в top-K

**Ключевая метрика для RAG: нашёлся ли нужный документ.**

| Модель | Hit@1 | Hit@3 | Hit@5 | Hit@10 |
|---|---|---|---|---|
| **BAAI/bge-m3** | **0.800** | 0.933 | 0.933 | 0.933 |
| `intfloat/multilingual-e5-small` | 0.733 | 0.933 | **1.000** | **1.000** |
| `intfloat/multilingual-e5-large` | 0.800 | 0.933 | 0.933 | **1.000** |

### nDCG@K и MRR@K — качество ранжирования

| Модель | nDCG@1 | nDCG@3 | nDCG@5 | MRR@5 |
|---|---|---|---|---|
| **BAAI/bge-m3** | **0.800** | 0.623 | 0.589 | 0.867 |
| `intfloat/multilingual-e5-small` | 0.733 | **0.631** | **0.605** | 0.850 |
| `intfloat/multilingual-e5-large` | **0.800** | 0.619 | 0.557 | 0.867 |

### Recall@K — доля релевантных чанков в top-K

| Модель | R@1 | R@3 | R@5 | R@10 |
|---|---|---|---|---|
| **BAAI/bge-m3** | **0.219** | 0.237 | 0.286 | **0.323** |
| `intfloat/multilingual-e5-small` | 0.215 | **0.270** | **0.288** | 0.319 |
| `intfloat/multilingual-e5-large` | 0.186 | 0.238 | 0.250 | 0.291 |

> **Почему Recall@K низкий?** Ground truth — **все** чанки документа
> (~9.4 чанка в среднем). Даже при идеальном поиске top-5 не может
> покрыть все 9.4 чанка, поэтому верхняя граница R@5 ≈ 0.53. Значение
> 0.25–0.29 означает, что модель находит 3 из 5 верхних позиций в
> правильном документе.

## Интерпретация

**1. E5-large — аутсайдер.** Проигрывает по всем метрикам при размере
2.2 ГБ, как у BGE-M3. В production не имеет смысла.

**2. E5-small и BGE-M3 сопоставимы.**
- E5-small чуть лучше по **Hit@5** (1.000 vs 0.933) и nDCG@3/@5.
- BGE-M3 чуть лучше по **Hit@1** (0.800 vs 0.733), nDCG@1 и Recall@10.

Разница — **в пределах статистической погрешности** (15 вопросов,
±1 вопрос = ±0.067). Нельзя утверждать, что одна модель «лучше»
другой на этом датасете.

**3. Разница между всеми тремя моделями мала.** На корпусе из 646
чанков современные мультиязычные модели работают сопоставимо. Это
ожидаемо: корпус небольшой, документы — связные технические тексты.

---

## Итоговое решение

**`BAAI/bge-m3`** выбрана как основная модель эмбеддингов, несмотря на
то, что по Hit@5 формально лидирует E5-small. Обоснование:

1. **Дополнительные возможности.** Matryoshka (сжатие размерности
   1024 → 512 → 256 без переобучения) и dense+sparse из коробки
   (гибридный поиск `RAG_USE_HYBRID=true` без доп. моделей).
2. **Лицензия MIT** и зрелое сообщество — проще поддерживать и
   передавать заказчику.
3. **Размерность 1024** — оптимальный компромисс между качеством и
   объёмом Qdrant (646 × 1024 × 4 ≈ 2.52 МБ на коллекцию).
4. **Качество на Hit@1** — самое важное для UX: пользователь чаще
   получает правильный документ сразу.
5. **На нашем корпусе разница с E5-small мала** — выбор продиктован
   не «победой в метриках», а совокупностью свойств.

E5-small как альтернатива **остаётся в резерве** для сценариев с
жёсткими ограничениями по памяти: 384-мерные векторы в 2.7 раза
меньше, что даёт экономию на Qdrant при том же качестве поиска.

## Технические детали

- **Размерность**: 1024 (полная BGE-M3), коллекция Qdrant `rag_block_04`.
- **Distance**: `COSINE` — см. [vector_store.md](vector_store.md).
- **Batch size индексации**: 32 (в `ingestion.py`).
- **Trust remote code**: `true` (обязательно для BGE-M3).
- **Инструкции**: для BGE-M3 не требуются, для E5 добавлены
  автоматически в скрипте сравнения (`"query: "` / `"passage: "`).
- **Офлайн-режим**: `HF_HUB_OFFLINE=1` при запуске — модели берутся
  из локального кеша, без обращений к huggingface.co.

---

## Ограничения

- Golden dataset из 15 вопросов — репрезентативен для дипломного
  проекта, но для production потребуется расширение до 50–100 вопросов.
- Разница между BGE-M3 и E5-small лежит в пределах погрешности —
  **честно зафиксировано**, чтобы не выдавать шум за результат.
- Метрики IR не учитывают качество генерации — за это отвечает
  [quality_report.md](quality_report.md) (RAGAS).
- Ground truth document-level: оценивается, найден ли правильный
  документ, а не конкретный чанк с ответом. Для RAG это правильнее —
  LLM потом сама выберет нужный фрагмент.
