# Схема агентного графа

Агент реализован на **LangGraph** (см. `app/services/agent_persistent.py`).
Топология — ReAct-цикл с поддержкой **human-in-the-loop** для действий,
требующих подтверждения пользователя (отправка email).

## Диаграмма

![Граф агента](agent.png)

Mermaid-исходник: [`agent-graph-custom.mmd`](agent-graph-custom.mmd).

## Узлы

| Узел | Назначение |
|---|---|
| `call_model` | Вызов LLM с текущим состоянием диалога и доступными инструментами |
| `execute_tool` | Выполнение **безопасных** инструментов (`search_knowledge_base`, `multiply`) |
| `prepare_email` | Формирование черновика письма (тема, тело, вложения) — **без отправки** |
| `confirm_and_send` | Точка `interrupt()` — приостановка до подтверждения, затем отправка через SMTP |
| `force_finish` | Принудительное завершение при отсутствии tool_calls или превышении лимита итераций |

## Переходы

| Откуда | Куда | Условие |
|---|---|---|
| `START` | `call_model` | Всегда |
| `call_model` | `prepare_email` | LLM вернула `send_email` tool_call |
| `call_model` | `execute_tool` | LLM вернула другие tool_calls |
| `call_model` | `force_finish` | Нет tool_calls **или** превышен лимит итераций |
| `execute_tool` | `call_model` | Всегда (возврат результата инструмента в LLM) |
| `prepare_email` | `confirm_and_send` | Всегда |
| `confirm_and_send` | `force_finish` | После подтверждения и отправки (или отказа) |
| `force_finish` | `END` | Всегда |

## Human-in-the-loop

Ключевая особенность графа — **отправка email никогда не происходит без
подтверждения пользователя**. Сценарий:

1. Пользователь: «Отправь заявку в HelpDesk».
2. `call_model` формирует tool_call `send_email`.
3. `prepare_email` создаёт черновик и сохраняет его в state.
4. `confirm_and_send` вызывает `interrupt()` — граф приостанавливается,
   пользователю через Telegram уходит inline-клавиатура с кнопками
   «Отправить» / «Отмена».
5. Пользователь нажимает кнопку → backend вызывает `/agent/resume` →
   граф продолжается с точки останова.
6. Если «Отправить» — SMTP-отправка. Если «Отмена» — выход без отправки.
7. `force_finish` завершает сессию.

## Персистентность

Состояние графа сохраняется в **Postgres** (`AGENT_CHECKPOINTER=postgres`)
после каждого узла. Это даёт:

- восстановление после `interrupt` — `/agent/resume` поднимает state из БД;
- устойчивость к перезапуску backend — незавершённые сессии не теряются;
- аудит — все шаги диалога восстановимы.

## Ограничения графа

- **Один агент с инструментами.** Мультиагентность не используется —
  избыточна для текущих задач.
- **Нет ветки ошибок.** Исключения инструментов обрабатываются внутри
  узлов и возвращаются в LLM как `ToolMessage` с текстом ошибки — модель
  видит проблему и может перестроить стратегию.
- **Лимит итераций.** Защищает от зацикливания `call_model ↔ execute_tool`.
  Значение лимита задаётся в коде агента.
